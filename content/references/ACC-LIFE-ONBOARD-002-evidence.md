## 2. 连续正常案例与答案链

示范使用案例基金 晨光（初始资产净值与份额均为 60,000,000），综合实务使用另一套资料：案例基金 晚风（48,000,000）。两套资料均为正常、充分、无冲突的脱敏合成资料，数字不同但结构同构。

### 2.1 正常示范：案例基金 晨光

1. 基金合同摘要载明 2026-03-10 至 2029-03-09，契约型开放式；托管协议摘要载明托管费按日计提、按月支付。
2. 成立确认资料载明 2026-03-10 成立，初始资产净值 60,000,000 元、初始份额 60,000,000 份。
3. 管理人参数确认函载明单位净值保留 4 位小数、申购/赎回结转 T+2、电子对账关键项为银行存款与实收资本。
4. 复算初始单位净值：`60,000,000 ÷ 60,000,000 = 1.0000` 元。
5. 首日账务：借 银行存款 60,000,000 元、贷 实收资本 60,000,000 元；估值表基金资产净值 60,000,000 元；电子对账银行存款与实收资本一致。

### 2.2 综合实务：案例基金 晚风

本案题面批准参数只对本题有效：初始单位净值 = 初始资产净值 ÷ 初始份额；单位净值保留 4 位小数；TA 结转申购/赎回 T+2；电子对账关键项为银行存款、实收资本；首日账务为借 银行存款 / 贷 实收资本。

| 环节 | 计算/取数 | 答案 |
| --- | --- | ---: |
| 初始资产净值 | 成立确认资料 | 48,000,000.00 |
| 初始份额 | 成立确认资料 | 48,000,000 份 |
| 初始单位净值 | `48,000,000 ÷ 48,000,000` | 1.0000 |
| 首日借方科目 | 首日账务 | 银行存款 |
| 首日贷方科目 | 首日账务 | 实收资本 |
| 首日账簿银行存款 | 银行到账资料 | 48,000,000.00 |
| 首日估值表基金资产净值 | 账簿与成立确认 | 48,000,000.00 |
| 电子对账结论 | 银行存款/实收资本关键项一致 | BALANCED |

参数设置复核表依据链：成立日期→成立确认资料；到期日期→基金合同摘要；托管费计提→托管协议摘要；TA 结转与电子对账关键项→管理人参数确认函。

## 3. 四环节与评分约束

- 知识卡：三张卡覆盖依据层级、参数对象与下游影响、首日结果验证。
- 正常示范：五步贯穿案例基金 晨光的资料读取、参数核对、初始净值复算、首日账务估值和电子对账验证。
- 基础练习：Q1 `FIELD_MAP` 资料与参数依据映射，Q1 的 `source` 行为脱敏字段片段（实际日期、合同期限、费用安排、TA/对账参数），不直接出现资料名称，学员依据字段事实判断来源；Q2 `ORDERING` 接管顺序，Q3 `CALCULATION` 初始资产/份额/单位净值取数与复算，Q4 `LEDGER_ENTRY` 首日账务科目补全，Q5 `RECONCILIATION` 账簿—估值—电子对账跨来源复核；五种认知动作不同，不是换皮选择题。
- 综合实务：十份资料组成案例基金 晚风的正常资料包，实际 JSON 为 14 个结构化工作项，Rubric `referenceAnswer.responses` 与之逐项对应，覆盖 FIELD_MAP、CALCULATION、LEDGER_ENTRY、RECONCILIATION 和 SHORT_TEXT。
- Rubric 固定为 CONCEPT 25 / PROCESS 30 / RISK 25 / EXPRESSION 20，通过线 75；设置两项硬性必达：关键设置绑定正确业务依据，初始资产/份额/单位净值/账簿/估值/电子对账闭合。`C-ONB-CONCEPT-PARAMETER` 指向 `R-ONB-SETUP`，确保参数理解缺口可触发补学；`C-ONB-EXPR-RESULT` 检查结论包含 `48000000`、`1.0000`、`银行存款`、`实收资本` 和 `一致`。
- 补学按认知动作命中真实缺口：`R-ONB-SOURCE`/`R-ONB-SETUP` → Q1/Q2，`R-ONB-NAV` → Q3，`R-ONB-LEDGER` → Q4，`R-ONB-RECON`/`R-ONB-EXPRESSION` → Q5；不引入异常案例、升级写作、独立问答或额外评分维度。

## 4. 范围边界

本路线只制作普通契约型开放式基金的新产品接管正常业务。ETF 成立批量导入、代码段配置、预期信用损失、历史费率/菜单/固定时点、FOF/货币基金/券结/ETF 等特殊产品参数不进入主链；复杂参数只作“识别后返回手册”的边界说明。综合实务不含缺失、冲突、迟到、越权或强制处理写作。
