# 监督世界验收矩阵

主 Agent 每个阶段只在“证据”和“门禁”同时满足时标记 `PASSED`。计划必须明确 `targetMode: PUBLISH_OPEN | BUILD_ONLY`；精确入口“开始制作监督世界，持续施工到完成”默认 `PUBLISH_OPEN`，只有明确的“只审计/只设计/只施工不发布”才使用 `BUILD_ONLY`。命令以仓库 `README.md`、`AGENTS.md` 和现役脚本为准；不要为了形式运行与本批无关的检查。

| 阶段 | 必须有的证据 | 主 Agent 门禁 | 失败或停止条件 |
| --- | --- | --- | --- |
| 全局模式 | 计划中的 `targetMode`、模式来源和允许的发布动作 | `PUBLISH_OPEN` 在路线内容/业务/确定性校验通过后必须应用候选开放登记，再做候选工作树浏览器验收；`BUILD_ONLY` 不应用候选登记，始终保持 `BUILDING`，完整浏览器验收为 `DEFERRED`；不向普通调用者增加选择题 | 模式缺失、互相冲突或开放要求改变通用契约、UI 结构、数据库、评分维度或视觉 |
| 0 前置 | Git 基线、分支、精确 writeSet、现役文档、材料绝对路径、敏感边界、计划初稿 | 既有修改/未跟踪路径与 writeSet 完全不重叠；默认材料路径存在、可读且非空；无界搜索未发生 | 任一路径重叠立即 `BLOCKED` 请求决定；默认材料不存在、不可读或为空立即 `BLOCKED` 索要绝对路径 |

| 发布收口 | `targetMode`、候选工作树状态、`git diff --check`、`git status`、敏感文件扫描、提交/推送结果、远端一致性和开放态 smoke | 只有授权文件变化；主 Agent 已复核全部子代理回报；`PUBLISH_OPEN` 浏览器通过后才 commit/push，且本地/远端提交一致、开放态 smoke 通过；`BUILD_ONLY` 有未应用候选登记/保持 `BUILDING`/浏览器 `DEFERRED` 证据 | 发现敏感内容、他人改动被覆盖、候选状态丢失、远端/本地不一致或 smoke 失败；不得强推/重写 |

## 按路径选择检查

- `content/`、`contracts/` 或 sources：运行 `.\scripts\validate-content.ps1`，并核对发布清单和 Schema；若文字变化，运行 `py -3 .\scripts\verify-text-humanization.py`。
- `backend/`、迁移、评分或安全投影：运行 `.\scripts\test-backend.ps1`，必要时再运行 `.\scripts\build-app.ps1`。
- `frontend/`：运行 `.\scripts\build-frontend.ps1` 及仓库现役类型/页面/视觉门禁；不得把视觉门禁改成通过。
- 跨端纵向闭环：运行 `.\scripts\verify-all.ps1`；涉及综合实务、补学、重做、历史或解锁时运行 `.\scripts\verify-phase4.ps1`。
- 无论改动范围如何，最终都做 `git diff --check`、`git status --short` 和敏感文件检查；构建产物、数据库、日志、`.local/` 不得提交。
