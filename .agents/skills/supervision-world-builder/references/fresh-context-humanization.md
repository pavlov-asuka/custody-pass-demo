# Fresh-context 去 AI 味检查

目标是让学员看到业务人员会说的话，而不是让文字失去专业精度。审查者必须保留业务术语、字段名、金额、日期、单位、公式、答案、Rubric、评分维度、硬性要求、现役路线拓扑、视觉和交互契约。

## 1. 路线与资料内容

逐条路线检查知识卡、正常示范、基础练习、综合实务资料包、结构化工作纸和补学文案：

- 删除课程作者旁白（例如“本关将带你”“让我们一步一步”）、泛化鼓励、空泛能力评价和评测器腔；
- 改成“业务对象 + 具体动作 + 可核对结果”，明确资料、字段、金额、状态、计算、勾稽或下一动作；
- 不把正常业务改写成异常升级话术，不新增材料没有支持的风险、制度、历史费率或案例；
- 检查同一路线的资料、示范、练习、答案、Rubric 和补学是否使用同一证据链，数字可复算，结构化工作纸不是长文本替身；
- 保护四环节顺序和 `BUILDING/DEFER` 边界，不通过删掉难点或降低答案要求来“去味”。

## 2. 前端可见表现

fresh-context 审查者用当前界面和代码检查动态状态、按钮、进度、评分结果、补学、重做、历史和错误提示：

- 页面直接说资料、字段、金额、状态或下一动作；
- 内部活动枚举、字段 ID、状态码、私有评分键只留在提交/评分机制，通过业务中文显示；
- 不出现模型名、提示词、接口字段、评测器自称、开发日志或“能力未体现/继续进步”等泛话术；
- 不改变 `frontend/DESIGN.md` 的布局、地图、色彩、小托、庆祝反馈、桌面端边界来解决文案问题；
- 不让前端推导通过、解锁或进度，不改变公开契约安全投影。

## 3. 后端评分与补学

检查后端返回的四维证据、硬门槛、未掌握结论、补学目标和重做提示：

- 反馈指向真实缺口：来源判断、字段读取、计算、账务/台账填写、勾稽、状态或结论；
- 保留概念、处理步骤、风险意识、表达规范的现役权重和服务端裁决，不以改文案绕过分数或硬性要求；
- 技术失败、学习未达标、通过后的复习和历史快照仍语义分离；补学不会直接改成通过；
- 私有答案、Rubric、关键词和模型参数不进入公开响应；内部码只做显示映射，不改提交值和评分键。

## 4. 浏览器盲测

在隔离运行时按真实学员顺序完成：登录、知识卡、正常示范、基础练习、综合实务、第一次未掌握、定向补学、结构化重做、通过、下一节点解锁和历史查看。记录首次遇到的课程腔、内部码、状态错位、空泛反馈、数字/单位错误或重复文案，再交给 fresh-context 写入子代理逐项修复。修复后重走受影响链路，并运行 `README.md`/`AGENTS.md` 指定的最小确定性验证。

## 保留/删除判定

| 保留 | 删除或改写 |
| --- | --- |
| 专业术语、字段、金额、公式、答案、Rubric、评分维度、状态和路线关系 | 作者旁白、模型/接口自指、评测器腔、泛化陪练话术、内部标签裸露 |
| 资料来源、计算过程、复算、勾稽、正常业务结论 | “继续进步”“能力未体现”“一步一步来”等不能定位缺口的反馈 |
| 视觉、拓扑、契约、数据库和安全边界 | 借去味之名改视觉、改路线、改评分或删除真实业务难点 |
