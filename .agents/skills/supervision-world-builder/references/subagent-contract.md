# 子代理调度协议

## 固定运行方式

所有直接子代理均使用模型 `gpt-5.6-luna`、推理强度 `max`，在当前正式仓库环境直接工作：不创建 worktree，不创建受控 Session，不自行改变 checkout。主 Agent 必须在派发请求中写明阶段、目标、精确输入路径、允许写入路径、禁止触碰的路径和已记录的 Git 基线/`writeSet`；没有通过重叠门禁的任务不得派发。

如果宿主支持 `fork_turns` 或同类参数，使用直接子代理能力并保持当前仓库上下文；不要把实质工作改造成独立线程或另一个 Git 检出。没有指定模型/强度的可用能力时应停下请求决定。

## 只读审计请求

请求必须包含：材料文件清单或对象分片、只读约束、要回答的证据问题、脱敏要求和回报格式。只读子代理不得写正式仓库、复制材料、创建路线或执行发布。

回报至少包含：

```text
材料对象：文件 / 页、表、段、图或嵌入对象
证据：字段、状态、数字、公式、顺序和来源位置
教学价值：可训练的业务动作与可验收结果
缺口与边界：矛盾、缺项、不可推断项、敏感项
建议状态：READY / BUILDING / DEFER
验证：使用的读取方式、复算或交叉核对
Git：只读，未修改；如发现起始脏改动，原样列出
```

多材料可并行只读，但主 Agent 只有在所有报告收齐并独立复核后才冻结拓扑。

## 设计与写入请求

路线设计子代理先根据已收齐的材料报告提出最小拓扑和批次建议；正式写入子代理只实现主 Agent 已冻结的批次。请求必须列出允许文件，要求保护现役视觉、契约、数据库、答案、评分语义和他人改动，并明确“不提交、不推送、不清理、不启动下一批”。子代理发现允许文件与基线中的任何既有修改/未跟踪文件重叠时，必须立即停止并回报 `BLOCKED`，不得覆盖或自行改写 writeSet。

写入回报至少包含：

```text
阶段/批次：
完成内容：
修改文件：逐项绝对或仓库相对路径
证据映射：原材料对象位置 → 内容字段/练习/评分证据
验证：命令、结果、未运行及原因
未完成/BUILDING-DEFER：
Git：status、diff 摘要；未 commit、未 push、未清理
下一动作建议：只建议，不执行
```

主 Agent 不把子代理的“通过”当作验收结论；必须重新读取关键 diff、运行与范围相称的测试并更新计划。

`PUBLISH_OPEN` 的候选登记子代理只在路线内容、业务和确定性校验通过后运行：把监督 map、新 release、sources、docs，以及从现役 `FormalContentCatalog`/active release selector 代码中发现的最小 selector、验证常量和相关测试接线应用到未提交工作树，使隔离构建能真正加载候选 release。它不得预设文件名，不得改通用契约、UI 结构、数据库、评分维度或视觉；必须回报完整候选 `status`/diff/未提交状态和 selector 关系，仍不得 commit、push、清理或回退他人改动。`BUILD_ONLY` 不派发该任务。

## 并行与串行

- A 阶段只读审计可按材料对象并行，报告不可互相覆盖。
- B0、每个 B 批次、统一登记和同一去味写入轮次默认串行。
- 只有两个写入子代理的绝对文件集合完全不重叠、不会改共享索引/发布清单/同一测试夹具，且主 Agent 已在计划中冻结并行窗口时，才允许并行。
- 前一阶段未通过门禁，不得派发后一阶段写入；后一阶段不得顺手修前一阶段以外的问题。

## Fresh-context 约束

去 AI 味审查必须新建与施工者无关的直接子代理上下文，给它当前文件和验收标准，不给“应该通过”的暗示。审查者先报告问题清单，再在主 Agent 指定的文件范围内修复；修复后必须再次回报证据和验证。若文字问题实际来自契约、评分、数据库或视觉结构，停在报告阶段请求主 Agent 决策，不私自扩大范围。
