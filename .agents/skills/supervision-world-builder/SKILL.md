# 监督世界施工

这是一个项目级施工 Skill。调用者只需从正式仓库根目录显式调用：

```text
$supervision-world-builder 开始制作监督世界，持续施工到完成
```

主 Agent 负责范围、阶段、调度、差异复核和最终发布；所有实质材料研究、路线设计、正式写入、修复和 fresh-context 验收都必须交给直接子代理。子代理固定使用 `gpt-5.6-luna`、`max`，不创建受控 Session 或 worktree。

## 入口纪律

1. 确认当前目录是正式仓库根目录，先读 `AGENTS.md`、`README.md`、`docs/current-state.md`、`docs/architecture.md`，再读与本批文件直接相关的契约、内容规范和 `frontend/DESIGN.md`。现役文档优先于历史交接、截图或提示词。
2. 先记录 Git 基线：`git status --short --untracked-files=all`、当前分支和计划候选写入路径。若任何既有修改或未跟踪文件与计划将写入的路径重叠，立即在计划记 `BLOCKED`、请求决定并停止；若重叠的正是计划文件本身，不得覆盖它，改为只读报告阻塞；子代理不得覆盖。没有重叠时原样保护既有改动，只在授权范围内继续。不能 stash、清理、覆盖或重写历史；干净且需要同步时在首次写入前对当前跟踪分支执行 `git pull --ff-only`；不创建分支或 worktree。
3. 原材料路径以用户显式给出的路径为准；显式路径不存在、不可读或为空时立即在计划记 `BLOCKED` 并请求修正。没有给出时只检查仓库外的 `../project_materials/新人陪练案例库/监督`，禁止无界搜索；默认路径不存在、不可读或为空时，立即在计划记 `BLOCKED`，向调用者索要绝对路径并停止，不进入审计或写入。
4. 在计划开始处写入 `targetMode`：精确入口“开始制作监督世界，持续施工到完成”默认是 `PUBLISH_OPEN`；只有调用者明确说“只审计”“只设计”或“只施工不发布”时才是 `BUILD_ONLY`，不要求普通调用者做模式选择。创建或更新 `docs/supervision-world-plan.md`，记录模式、范围、材料索引、拓扑、批次、文件所有权、阶段状态、证据、阻塞和下一动作。每个阶段完成后更新并重新读取该文件；压缩上下文后也必须先重新读取。

详细阶段协议见 [references/phase-workflow.md](references/phase-workflow.md)，子代理边界和回报格式见 [references/subagent-contract.md](references/subagent-contract.md)，逐阶段门禁见 [references/acceptance-matrix.md](references/acceptance-matrix.md)。按当前阶段读取所需参考，不把整个参考目录无差别塞入上下文。

## 必须遵守的施工形态

- 读审计可按材料对象并行；正式写入原则上一次只允许一个子代理。只有主 Agent 明确冻结且路径完全不重叠时才可并行写入。
- 阶段 A 完成对象级材料审计后，主 Agent 只冻结最小可证据化拓扑；资料不足的主题标为 `BUILDING/DEFER`，不能用通用话术补造课程。
- B0 先建立共享字段字典、状态链、脱敏边界和正常业务案例；B1…Bn 再按不重叠批次施工 route、四环节内容、结构化综合实务工作纸、Rubric、证据映射和确定性 verifier；随后进入统一 map、release、sources、docs 登记与发布门禁。
- 现役训练形态固定为知识卡、正常示范、基础练习、综合实务四环节。综合实务必须以正常业务资料包和结构化工作纸训练来源识读、字段读取、计算/复算、凭证或台账/报表填写、跨来源勾稽和简短结论；评分维度和通过语义以仓库现役契约为准。
- 全部内容批次施工和统一登记准备完成后才启动 fresh-context 去 AI 味：分别覆盖学员可见路线文字、前端动态显示与内部码映射、后端评分反馈与定向补学；`PUBLISH_OPEN` 在候选工作树上做真实浏览器闭环，`BUILD_ONLY` 的完整浏览器闭环标记 `DEFERRED`。保留业务术语、数字、公式、答案、Rubric、评分语义、现役拓扑和视觉基线，不改视觉、契约、数据库或公开安全边界来掩盖文字问题。
- `PUBLISH_OPEN` 在所有路线内容、业务和确定性校验通过后，先由登记子代理把候选开放登记应用到未提交工作树：监督 map、新 release、sources、docs，以及根据运行时 `FormalContentCatalog`/active release selector 发现的最小 selector、验证常量和相关测试接线；随后基于这份候选工作树做 fresh-context 与真实浏览器闭环，全部通过后主 Agent 才提交并推送。这个最小发布接线不授权改变通用契约、UI 结构、数据库、评分维度或视觉；若开放必需这些变化，立即暂停请求决定。`BUILD_ONLY` 不应用候选开放登记，只做内容、业务和确定性验证，监督世界保持 `BUILDING`，完整浏览器验收标为 `DEFERRED`，不得宣称正式开放闭环完成。
- 调用文本已明确“持续施工到完成”时，视为对整条施工链的授权，阶段之间自动继续；只有材料缺口、正式范围扩张、契约/UI/数据库边界变化或无法解决的阻塞才向调用者暂停请求决定。相同具体阻塞连续两次仍未解决就停止，不创建第三次重试或旁路代理。
- 子代理不得提交、推送、清理、改变范围或启动下一批；必须回报文件范围、证据、验证结果和 Git 状态。候选开放工作树上的浏览器失败只修本批；同一具体阻塞两次就停止，不提交/推送、不清理或回退他人改动，并在计划记录候选工作树状态。主 Agent 独立复核后运行与改动范围相称的确定性测试、隔离构建和真实浏览器验收，最后检查敏感内容、`git diff --check` 与 `git status`，再在当前跟踪分支统一提交并推送；推送后核对本地与远端提交完全一致并做最小开放态 smoke，任何不一致或 smoke 失败都停止，不强推或重写历史。

若当前宿主无法直接派发指定的 `gpt-5.6-luna`/`max` 子代理，暂停并说明，不降级为主 Agent 代做实质研究或施工。
