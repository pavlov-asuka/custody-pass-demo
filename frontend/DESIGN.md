# 托管智训营桌面端视觉设计规范

> 阶段 3B 唯一视觉事实源
> 适用基线：`025a0ebe9bfe5ed12a194ce94ff767d9eb69ba68`
> 适用范围：托管智训营前端桌面端页面、状态、组件、插画和视觉验收

## 1. 权威层级与适用边界

### 1.1 权威层级

发生冲突时，按以下顺序执行：

1. 已确认的产品结构、业务规则、接口契约和评分语义；
2. 本文件；
3. 已通过用户视觉闸门的阶段 3B 截图；
4. Duolingo 官方品牌规范中可迁移的稳定视觉原则；
5. Refero、Figma 社区复刻和 Banani 截图等研究证据；
6. 施工人员的临时判断。

第三方研究材料只用于解释设计规律，不是本项目的直接组件规范。社区 Figma 不是官方稿，Banani 截图的采集年代不确定，Refero 主要反映营销视觉；不得用任何单一来源覆盖本文件。

### 1.2 固定产品容器

本规范只能融入视觉语言，不得更换以下产品结构：

- 登录后进入清算、核算、监督三个大型学习世界；
- 首版只有核算可进入，清算和监督显示建设中；
- 核算世界采用连续纵向长地图；
- 一个路线对应一个地图节点；
- 路线内固定为知识卡、正常示范、基础练习、异常案例四环节；
- 正式提交后异步评分；
- 结果包含四维结果；
- 未掌握后进入定向补学，再进行完整案例重试；
- 训练记录只位于用户菜单；
- 小托仅按情景出现。

### 1.3 平台边界

本项目只设计和验收桌面端。不得引入移动端布局、导航、尺寸、触控习惯、安全区或适配方案。研究材料中的手机截图仅曾用于提取跨端稳定的色彩、字重、留白、圆角、描边、按压深度、节点、插画和反馈规律，不构成页面布局依据。

## 2. 设计目标与原则

### 2.1 核心目标

把成熟、友好、节奏清晰的学习产品语言完整融入托管业务，同时保留真实术语、事实、凭证、日期、角色、任务和审计状态带来的专业可信度。

统一体验链条：

> 白色安静基线 → 单一学习主体 → 稀疏而明确的可操作节点 → 操作后释放语义色、按压深度和角色情绪

### 2.2 六项原则

1. **学习路径优先**：地图页首先看见路径，学习页首先看见当前任务，结果页首先看见结论。
2. **一屏一个主动作**：读、观察、作答、等待、复盘或补学不能同时争夺视觉主位。
3. **颜色有唯一语义**：颜色不做无目的装饰，不让同一颜色承担冲突状态。
4. **深度只属于可按压物**：按钮和地图节点可有按压深度，静态容器保持安静。
5. **角色服务情景**：小托是叙事标点，不是常驻客服挂件。
6. **友好不等于幼稚**：圆润、留白和温和反馈服务理解；业务事实、术语和证据保持准确、克制。

## 3. 桌面画布与页面宽度

### 3.1 验收画布

- 必测：`1440 × 900`；
- 必测：`1920 × 1080`；
- 顶栏：64—72px；
- 页面主壳最大宽：1180—1200px；
- 页面顶部主内容留白：48—64px；
- 页面左右安全留白：在两档画布中不得小于 32px。

### 3.2 内容宽度

| 场景 | 推荐宽度 |
|---|---:|
| 三世界主区域 | 1180—1200px |
| 地图、知识卡、正常示范、基础练习主体 | 640—760px，目标 720px |
| 异常案例双栏 | 1040—1120px |
| 结果与定向补学 | 880—1040px |
| 训练记录与记录详情 | 1040—1120px |
| 用户菜单 | 280—320px |

长文本建议每行 28—40 个中文字符。不得用巨型 Hero、概要卡或装饰区把学习主体推到首个桌面视口以下。

## 4. 字体

### 4.1 字体策略

首选自托管：

- 拉丁字母、数字：Nunito；
- 中文：Noto Sans SC；
- 只引入实际使用的必要字重：400、500、700；
- 正文不得普遍使用 700，任何页面不得普遍使用 800/900。

回退系统字体栈：

`"Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", system-ui, sans-serif`

### 4.2 小于 10 MB 的硬门槛

前端实际发布的全部自托管字体文件，在发布压缩口径下合计必须**严格小于 10 MB**。

- 优先 WOFF2；
- 仅保留 400、500、700 必要字重；
- 优先制作中文字符子集并移除未使用字形；
- 必须测量构建产物，不得只看源文件或理论估算；
- 测量必须覆盖全部实际发布字体文件，不能遗漏异步块或公共目录资源；
- 同时记录字体原始字节合计和发布压缩字节合计；
- 当授权、子集可靠性、字符覆盖或技术条件无法证明达标时，必须删除自托管字体引用并回退系统字体栈；
- 不得为了视觉效果突破 10 MB，不得引入完整、未裁剪、多字重中文大字体包。

### 4.3 字级

| 角色 | 字号 | 字重 | 行高 |
|---|---:|---:|---:|
| 页面主标题 | 30—36px | 700 | 1.25 |
| 场景主标题 | 36—44px | 700 | 1.2 |
| 区块标题 | 22—26px | 700 | 1.35 |
| 卡片/问题标题 | 18—20px | 700 | 1.45 |
| 正文 | 16px | 400/500 | 1.6—1.7 |
| 控件文字 | 15—16px | 700 | 1.3 |
| 标签/辅助信息 | 12—14px | 600/700 | 1.4 |
| 结果大数字 | 40—52px | 700 | 1.1 |

中文不使用全大写模拟强调。标题可轻微收紧字距，正文保持正常字距。

## 5. 颜色及唯一语义

### 5.1 基础色

| 名称 | 色值 | 唯一职责 |
|---|---|---|
| 画布白 | `#FFFFFF` | 页面和主要阅读画布 |
| 近白底 | `#F7F7F7` | 极轻分区、禁用或背景层 |
| 主文字 | `#4B4B4B` | 标题、正文、主要结构 |
| 次文字 | `#777777` | 辅助说明、次要元数据 |
| 浅灰边 | `#E5E5E5` | 普通 1px 分隔和边界 |
| 禁用灰 | `#AFAFAF` | 锁定、禁用、低强调 |

### 5.2 语义色

| 名称 | 色值 | 唯一语义 |
|---|---|---|
| 推进绿 | `#58CC02` | 当前推进、可进入、成功 |
| 选中蓝 | `#1CB0F6` | 选中、聚焦、信息 |
| 引导黄 | `#FFC800` | 引导、等待、需注意 |
| 补学橙 | `#FF9600` | 未掌握后的补强方向 |
| 错误红 | `#FF4B4B` | 技术失败或明确错误 |
| 辅助紫 | `#CE82FF` | 插画局部和非状态装饰，不作为主交互色 |

同一状态必须同时具备文字、图标或形状提示，不得只靠颜色。红色不得用于普通提醒；绿色不得用于一般标题装饰；蓝色不得与主行动竞争。

### 5.3 颜色面积

- 白色与近白：每个桌面视口 75%—85%；
- 普通信息页的高饱和 UI 面积：不超过约 8%；
- 地图和结果页的高饱和 UI 面积：不超过约 12%；
- 单个视口最多一个大面积饱和色带；
- 插画色不计入交互色面积，但不得形成满屏彩色背景。

## 6. 间距

基础单位为 4px。允许值优先使用：

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80`

| 关系 | 间距 |
|---|---:|
| 图标与文字 | 8—12px |
| 同组控件 | 12—16px |
| 卡片内边距 | 20—24px |
| 题干与材料 | 24—32px |
| 区块之间 | 32—48px |
| 页面章节之间 | 48—64px |
| 小托与正文、控件、路线净距 | 至少 24px |

不得用连续边框代替留白分组。

## 7. 圆角、边框与按压深度

### 7.1 圆角

| 元素 | 圆角 |
|---|---:|
| 按钮、输入、选项 | 14—16px |
| 轻容器 | 16—20px |
| 大型世界场景 | 24—32px |
| 药丸标签 | 999px |
| 地图圆节点 | 50% |

### 7.2 边框

- 普通静态容器：无边框或 1px 浅灰；
- 输入、选项和次按钮：1—2px；
- 彩色 2px 边框：只用于选中、正确、错误、聚焦等状态；
- 顶栏和列表分隔：1px 浅灰；
- 禁止 3px 深蓝或深灰描边遍布页面。

### 7.3 阴影和按压深度

- 主按钮：0 模糊、垂直 4px 的深色同相色；
- 地图节点：0 模糊、垂直 6—8px；
- 小按钮：0 模糊、垂直 2—3px；
- 按下态：主体向下位移，视觉深度缩小或归零；
- 菜单可使用轻柔环境阴影，但不得模拟按压；
- 静态卡片、记录行、筛选框、结果块不得使用硬下沿；
- 禁止玻璃拟态、炫光、重投影和悬浮卡片墙。

## 8. 图标与插画

### 8.1 图标

- 常规图标：20—24px；
- 地图节点图标：30—38px；
- 线宽：2—2.5px；
- 采用圆端、圆角、少量必要几何；
- 图标必须配合文字或可访问名称，不承担完整业务解释；
- 不使用多套风格混杂的图标库。

### 8.2 插画语言

- 使用圆形、圆角矩形、圆角三角形等简单几何；
- 形状少而明确，平面视角，避免尖锐和复杂写实纹理；
- 地面影子使用扁平药丸形，不做写实光影；
- 人物姿态和视线服务当前情景；
- 不复制 Duolingo 角色、商标、专有文案或游戏资产。

## 9. 地图节点与路线

### 9.1 地图几何

| 类型 | 尺寸 |
|---|---:|
| 普通路线节点 | 76—80px |
| 当前节点 | 88—96px |
| 里程碑节点 | 100—104px |
| 支线/补学节点 | 60—64px |
| 节点纵向节距 | 104—120px |
| 路线标签宽 | 150—190px |
| 路径线宽 | 8—12px |

地图主轴宽 640—760px，目标 720px。节点标签常显，必须直接写出路线名称，不能要求用户猜图标。

### 9.2 状态

- **当前**：推进绿节点、最大视觉权重、明确“继续”；
- **已通过**：绿色或中性色完成标记，弱于当前节点；
- **未掌握**：补学橙，配文字和补学入口；
- **锁定/建设中**：灰色、无按压深度、无误导性按钮；
- **评分中**：引导黄或中性等待符号，不伪造百分比；
- **技术失败**：局部错误红，明确可重试。

首个桌面视口必须同时看到当前单元、当前节点、至少一个后继节点和路径继续方向。路径始终高于章节装饰、角色和统计摘要。

## 10. 三世界场景

- 三个世界等宽、等高、并列，建议每个约 360 × 500—540px；
- 场景插画区 220—280px；
- 下部只放名称、一句职责、状态、必要进度和行动；
- 清算、核算、监督通过场景和图标区分，不建立三套主色体系；
- 只有核算显示推进绿可行动按钮；
- 清算和监督显示明确“建设中”，无按压深度，不做假按钮；
- 三张入口应像三座开放式学习世界，不像企业门户卡片。

首批三张门槛页面必须使用接近最终品质的三世界场景，不得用影响气质判断的低保真占位图。

## 11. 顶栏与用户菜单

### 11.1 顶栏

- 高 64—72px；
- 最大内容宽 1180—1200px；
- 左侧 Logo，右侧用户头像；
- 只用 1px 浅灰底分隔；
- 不放三条线快速切换、经验值、连续学习或多标签后台导航。

### 11.2 用户菜单

- 宽 280—320px；
- 轻边框或轻环境阴影；
- 训练记录入口明确；
- 菜单项高 44—48px；
- 不覆盖关键学习内容，不使用深色粗框和硬下沿。

## 12. 四环节共同规范

环节顺序固定为：

1. 知识卡；
2. 正常示范；
3. 基础练习；
4. 异常案例。

共同结构：

- 顶部进度区内容宽 960—1000px，高 48—64px；
- 主任务区按本页内容宽居中；
- 底部行动区高 88—104px；
- 顺序为进度 → 题干/标题 → 必要材料 → 当前动作 → 局部反馈 → 唯一主行动；
- 不使用侧栏和多张说明卡争夺当前任务；
- 环节状态必须由后端事实或现有契约提供，不由前端推导。

## 13. 各学习环节

### 13.1 知识卡

- 一屏一个知识主题；
- 以正文、示意和关键事实为主，不做卡片网格；
- 关键术语可以淡色块强调，但每屏不超过 3 个；
- 正文主体宽 640—720px；
- 唯一主行动为继续进入正常示范。

### 13.2 正常示范

- 用清晰顺序呈现事实、处理动作、结果和原因；
- 示例本体与解释层级分开；
- 允许步骤线、编号或局部高亮，不把每一步做成重卡；
- 保留托管业务术语、凭证字段和处理依据。

### 13.3 基础练习

这是首批视觉门槛的典型学习环节母版。

- 主列 680—760px；
- 必须设计未选择、已选择、提交后反馈三态；
- 未选择：1px 浅灰边；
- 已选择：2px 选中蓝边 + 淡蓝底；
- 正确：2px 推进绿边 + 淡绿底；
- 明确错误：2px 错误红边 + 淡红底；
- 未选择时提交按钮不可用，且有文字/形状差异；
- 提交后局部反馈先于下一步行动；
- 不新增独立问答产品入口。

### 13.4 异常案例

- 保留 1040—1120px 双栏；
- 左右建议约 36/64，分别承载任务背景/提示与专业材料/作答；
- 表格、凭证、日期、机构、金额、状态和证据保持专业密度；
- 视觉辅助不得遮挡或简化关键业务事实；
- 正式提交后进入异步评分，不在前端伪造评分。

## 14. 评分、结果与补学

### 14.1 评分等待

- 明确“已提交”和“系统处理中”；
- 告知用户可等待或按现有能力安全离开；
- 不展示无依据的百分比或预计时间；
- 使用引导黄或中性动画，小托可用等待姿态；
- 不把等待页做成巨型结果卡。

### 14.2 评分技术失败

- 明确是技术问题，不是学习失败；
- 错误红只用于图标、标题或局部状态带；
- “重试评分/重试请求”为主行动，“返回”为次行动；
- 保留错误追踪信息所需的专业字段，但不暴露内部敏感细节；
- 小托使用故障协助姿态，不进行责备性表达。

### 14.3 通过结果

- 首屏先显示通过结论、路线名称和唯一下一行动；
- 四维结果完整保留，但视觉权重低于结论；
- 小托使用庆祝姿态，插画约 180—220px；
- 彩纸等庆祝元素稀疏，不覆盖业务证据；
- 不显示 XP、等级或连续学习奖励。

### 14.4 未掌握结果

- 首屏先给可恢复的未掌握结论；
- 明确薄弱维度、依据和推荐补学目标；
- 采用补学橙作为主状态，错误红只用于具体错误证据；
- 主要行动进入定向补学；
- 小托使用安慰/指路姿态，不使用惩罚语言。

### 14.5 定向补学

- 一次只补一个明确薄弱点；
- 顺序为薄弱结论 → 证据 → 补学内容 → 检查理解 → 完整案例重试；
- 不把补学做成后台任务列表；
- 支线节点 60—64px，完成后清楚回到原路线；
- 完整案例重试不可被拆成只重做错误小题。

## 15. 训练记录与记录详情

### 15.1 训练记录

- 位于用户菜单，不进入顶栏主导航；
- 主区域 1040—1120px；
- 列表优先，显示路线、时间、状态、结果和必要行动；
- 筛选器轻量，不使用硬阴影；
- 空状态由小托提供一次说明，不常驻；
- 不做排行榜或同伴比较。

### 15.2 记录详情

- 顺序为历史结论 → 当时四维依据 → 当时关键作答/证据 → 当时补学或重试动作；
- 明确标注这是历史记录，不能误导为当前任务；
- 历史快照和当前路线状态分开；
- 保留审计所需的时间、版本和状态信息；
- 不用多张同权重结果卡堆叠。

## 16. 小托情景系统

### 16.1 核心姿态

首批门槛页及后续扩展至少形成：

| 情景 | 姿态职责 |
|---|---|
| 欢迎 | 建立进入感，不抢登录行动 |
| 指路 | 指向世界或当前路径 |
| 讲解 | 指向关键事实或示范步骤 |
| 等待 | 陪伴异步评分，不伪造进度 |
| 庆祝 | 强化通过结论 |
| 安慰 | 说明未掌握可恢复并指向补学 |
| 技术故障 | 区分系统问题与学习结果 |

### 16.2 尺寸与密度

- 三世界标题旁：100—140px；
- 地图：140—220px；
- 学习环节：120—180px；
- 结果：180—220px；
- 每个桌面视口最多一个主角色；
- 与正文、控件、路径保持至少 24px 净距；
- 不重复同一正面站姿，不把角色做成固定悬浮客服。

首批三张视觉门槛页直接使用接近最终品质的三世界场景和小托核心姿态。

## 17. 动效

- 按钮按下：80—120ms；
- 普通状态转换：150—220ms；
- 反馈带出现：180—260ms；
- 路径推进：300—500ms；
- 等待动画应循环平稳，不暗示虚假进度；
- 成功庆祝不超过 900ms，不能阻挡继续操作；
- 尊重用户减少动态效果设置；
- 禁止弹跳过度、连续晃动、炫光、长时间彩纸和装饰性自动播放。

## 18. 逐屏规范

## 19. 明确禁止项

1. 任何移动端研究、布局或施工。
2. 改变三世界、连续长地图、四环节、异步评分、四维结果、定向补学、完整案例重试和训练记录位置。
3. 引入 XP、等级、连续学习、红心、排行榜、独立问答或三条线快速切换。
4. 用绿色背景、卡通图标和大圆角做表面模仿。
5. 深蓝 3px 描边遍布页面。
6. 静态卡片、结果块和记录行使用硬下沿。
7. 正文和控件普遍使用 800/900。
8. 巨型 Hero、后台卡片网格和多层卡套卡。
9. 隐藏路线名称或只用图标解释业务。
10. 三条业务线各自建立冲突的组件和主色。
11. 小托无意义常驻、遮挡内容或重复单一站姿。
12. 复制 Duolingo 角色、商标、专有文案或游戏经济。
13. 渐变、玻璃拟态、炫光和大面积深色背景。
14. 用颜色作为唯一状态提示。
15. 前端推导通过、解锁、路线进度或评分结论。
16. 未经视觉闸门确认就批量扩展新的页面体系。

## 20. 逐屏验收清单

### 20.1 两档画布的全局检查

以下项目必须分别在 `1440 × 900` 和 `1920 × 1080` 截图中通过：

- [ ] 无移动端内容或适配设计。
- [ ] 主壳和页面主体宽度符合本规范，无横向溢出。
- [ ] 白/近白面积 75%—85%。
- [ ] 饱和色面积符合普通页 8%、地图/结果页 12% 上限。
- [ ] 字体文件策略已明确；自托管时发布压缩合计严格小于 10 MB。
- [ ] 无普遍 800/900 字重，正文可连续阅读。
- [ ] 静态容器无 3px 深色边和按压阴影。
- [ ] 按压深度只出现在按钮和节点。
- [ ] 状态同时有文字、图标或形状，不只靠颜色。
- [ ] 每个视口最多一个主角色，且有明确情景职责。
- [ ] 主行动唯一，键盘焦点清楚。
- [ ] 原路由、接口、状态和评分语义未改变。

### 20.2 页面检查

- [ ] **登录**：首屏只有一个明确登录行动；可信说明保留；无小组件堆叠。
- [ ] **三世界**：三世界同级可辨；仅核算可进入；建设中不可误点。
- [ ] **长地图**：首屏看见当前单元、当前节点、后继节点和继续方向；路线名常显。
- [ ] **知识卡**：一屏一个主题；无多层卡片；术语和依据完整。
- [ ] **正常示范**：处理链可顺序阅读；示例和解释层级明确。
- [ ] **基础练习**：未选、已选、反馈三态完整；提交条件清楚。
- [ ] **异常案例**：双栏关系清晰；专业材料不被插画遮挡。
- [ ] **评分等待**：明确已提交与处理中；不承诺虚假进度。
- [ ] **技术失败**：明确是系统问题；重试为主行动；红色受控。
- [ ] **通过结果**：先见通过结论与下一步；四维结果完整。
- [ ] **未掌握结果**：先见可恢复结论；薄弱维度和补学行动明确。
- [ ] **定向补学**：一次只补一个点；完整案例重试路径清楚。
- [ ] **训练记录**：列表可扫描；时间、路线、状态和结果齐全。
- [ ] **记录详情**：先历史结论再证据；历史与当前状态分离。
- [ ] **用户菜单**：训练记录入口清楚；面板轻量。
- [ ] **小托**：欢迎、指路、讲解、等待、庆祝、安慰、故障姿态可辨。

### 20.3 新页面视觉闸门

现有全页面视觉系统已经通过验收，最终基线位于 `frontend/screenshots/phase3b-final/`。后续新增页面或大规模调整时，应先选取最能覆盖新交互语法的少量关键页面：

1. 使用接近最终品质的场景和小托姿态；
2. 同时提交 `1440 × 900` 与 `1920 × 1080` 两档桌面截图；
3. 覆盖默认、交互和反馈关键状态；
4. 逐项通过本章检查后再扩展到其他页面。
