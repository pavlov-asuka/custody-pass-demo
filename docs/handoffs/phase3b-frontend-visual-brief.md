# 阶段 3B｜前端视觉重构施工 Brief

> 交付对象：后续阶段 3B 前端施工 session
> 功能基线：`025a0ebe9bfe5ed12a194ce94ff767d9eb69ba68`
> 唯一视觉事实源：`frontend/DESIGN.md`

## 1. 任务目标

在不改变阶段 3 功能、接口和状态机的前提下，将托管智训营重构为统一的桌面端学习产品视觉：

- 白色安静画布；
- 连续学习路径为视觉主体；
- 一屏一个学习动作；
- 操作后才释放明确的语义色、按压深度和情绪反馈；
- 三世界场景与小托姿态接近最终品质；
- 托管术语、事实、凭证、日期、角色和审计信息保持专业可信。

阶段 3B 解决视觉系统、必要的信息层级和布局问题，不推翻已通过复核的功能基线。

## 2. 非目标

- 不做移动端研究、布局、导航、尺寸或适配；
- 不新增产品功能；
- 不修改后端、接口契约、评分逻辑或数据模型；
- 不改变三世界、连续长地图、四环节、异步评分、四维结果、定向补学、完整案例重试和训练记录位置；
- 不复制 Duolingo 角色、商标、专有文案或游戏经济；
- 不启动阶段 4。

## 3. 功能基线与事实源

### 3.1 功能基线

唯一功能基线提交：

```text
025a0ebe9bfe5ed12a194ce94ff767d9eb69ba68
feat: rebuild phase three learning frontend
```

施工前记录当前分支、HEAD 和工作树状态。不得覆盖或清理既有未提交变化。施工过程中必须保持现有接口、路由、状态机、测试标识和后端推导规则。

### 3.2 视觉事实源

`frontend/DESIGN.md` 是阶段 3B 唯一视觉事实源。

优先级：

1. 已确认产品结构和业务规则；
2. `frontend/DESIGN.md`；
3. 已获用户确认的三张门槛页；
4. 研究来源。

Refero、社区 Figma 和 Banani 只能用于追溯研究证据，不能覆盖本项目规范，也不能被称为官方产品规范。

## 4. 允许与禁止修改范围

### 4.1 获正式启动授权后允许

- `frontend/` 内与阶段 3B 视觉直接相关的样式、组件、页面和本地插画资产；
- 必要的字体资产、字体声明和构建内引用；
- 与视觉状态直接相关、但不改变业务语义的组件拆分；
- 视觉回归截图和前端测试的必要更新；
- 阶段 3B 约定的前端文档。

每次修改必须能说明它服务于哪条 `frontend/DESIGN.md` 规则。

### 4.2 禁止

- `backend/`、数据库、接口定义、评分逻辑和内容库；
- 改动 API 路径、请求/响应结构、路由语义或测试标识；
- 前端自行推导通过、解锁、路线进度或评分结果；
- 引入 XP、等级、连续学习、红心、排行榜、独立问答或三条线快速切换；
- 新增未授权业务功能；
- 清理、格式化或顺手重构无关文件；
- 在三页视觉闸门通过前批量扩展；
- 阶段 3B 后自动开始阶段 4。

## 5. 用户已确认的资产策略

### 5.1 字体

- 自托管 Nunito + Noto Sans SC；
- 只使用 400、500、700 必要字重；
- 优先 WOFF2、中文子集和去除未使用字形；
- 前端实际发布的全部自托管字体文件，发布压缩后合计必须严格小于 10 MB；
- 无法可靠达标时回退 `frontend/DESIGN.md` 中的系统字体栈；
- 不允许以视觉效果为由突破上限。

### 5.2 插画

首批三张门槛页面直接使用接近最终品质的：

- 清算、核算、监督三世界场景；
- 小托核心姿态；
- 与项目统一的图标和场景几何。

不得用会妨碍整体气质判断的低保真占位插画。

## 6. 施工顺序

### 3B-0｜冻结和核验功能基线

1. 核验 HEAD 与基线提交关系；
2. 记录施工前工作树，不清理既有变化；
3. 运行并记录阶段 3 现有类型检查、页面测试和构建；
4. 保存现有关键路由、接口调用、测试标识和截图编号；
5. 扫描禁用机制，形成施工前基线；
6. 遇到功能基线失败或不明工作树冲突时停止并回报主控。

本步骤不得改视觉。

### 3B-1｜建立视觉基础

按 `frontend/DESIGN.md` 落地：

- 字体与回退栈；
- 颜色及唯一语义；
- 字级；
- 4px 间距体系；
- 圆角；
- 0/1/2px 边框规则；
- 按钮和节点按压深度；
- 图标几何；
- 插画语言；
- 动效时长与减少动态效果。

完成字体构建产物实测。不能证明严格小于 10 MB 时立即切换系统字体栈，不把问题留到最终验收。

### 3B-2｜建立公共组件

先建立或整理以下公共组件的视觉状态，再组装页面：

- `AppShell` / 轻量顶栏；
- 用户头像与用户菜单；
- 主按钮、次按钮、禁用按钮、按下态；
- 文本输入、选择项、正确/错误/聚焦态；
- 顶部环节进度；
- 底部行动区；
- 局部反馈带；
- 世界场景入口；
- 地图路径、单元标题、路线节点、节点标签；
- 锁定、当前、已通过、未掌握、评分中、技术失败状态；
- 知识正文与关键事实块；
- 正常示范步骤；
- 异常案例专业材料容器；
- 四维结果行；
- 定向补学目标；
- 记录列表和历史详情；
- Xiaotuo 情景角色与气泡。

静态容器不得复用按钮的硬下沿。状态不得只靠颜色表达。

### 3B-3｜只制作三张视觉门槛页

仅制作：

1. 三个大型学习世界入口；
2. 核算连续长地图；
3. 以基础练习为母版的典型学习环节。

不得在本步骤顺手扩展登录、其他三个环节、结果、补学或训练记录。

#### 门槛页 1：三世界入口

必须具备：

- 三世界默认完整场景；
- 核算可进入状态；
- 清算和监督建设中状态；
- 小托指路姿态；
- 按钮默认、悬停、聚焦、按下状态；
- `1440 × 900` 和 `1920 × 1080` 截图。

通过标准：像三座并列学习世界，不像企业门户卡；只有核算可行动。

#### 门槛页 2：核算连续长地图

必须具备：

- 当前节点；
- 已通过节点；
- 后继/锁定节点；
- 未掌握或补学节点的可验证状态；
- 单元标题和路线标签；
- 路径继续方向；
- Xiaotuo 地图指路姿态；
- `1440 × 900` 和 `1920 × 1080` 截图。

通过标准：首个桌面视口同时看到当前单元、当前节点、至少一个后继节点和继续方向；路径是绝对视觉主体。

#### 门槛页 3：基础练习母版

必须具备：

- 未选择；
- 已选择；
- 提交后正确反馈；
- 提交后明确错误反馈；
- 提交按钮禁用、可用、按下状态；
- 键盘焦点；
- Xiaotuo 讲解或反馈姿态；
- `1440 × 900` 和 `1920 × 1080` 截图。

通过标准：不依赖侧栏和多层卡片，用户一眼知道当前任务、能否提交和反馈结果。

## 7. 字体体积实测与失败回退

### 7.1 测量口径

以生产构建实际发布内容为准：

1. 完成生产构建；
2. 枚举构建输出和公共发布目录中全部实际发布的字体文件；
3. 核对浏览器最终引用的字体 URL，防止遗漏异步资源；
4. 记录每个文件名、格式、字重、字符子集、原始字节；
5. 使用与发布链路一致的压缩方式测量每个字体文件；
6. 汇总全部自托管字体的发布压缩字节；
7. 用字节值判断，必须 `< 10,000,000`；不得把等于 10 MB 视为通过；
8. 将命令、文件清单和汇总结果写入交付报告。

若部署平台还会二次封装，应采用更保守的结果，不得借十进制/二进制换算争议放宽上限。

### 7.2 字符覆盖

体积通过不代表字体通过。还必须覆盖：

- 当前全部界面中文文案；
- 路线、机构、角色和业务术语；
- 常用数字、日期、金额、标点；
- 运行时可能出现且已由产品契约允许的字符。

出现缺字、回退跳变、字重伪造或新内容无法可靠覆盖时，视为自托管方案失败。

### 7.3 回退条件和动作

任一情况触发回退：

- 发布压缩合计无法证明严格小于 10 MB；
- 字体授权不能确认；
- 子集工具或流程不可复现；
- 关键字符覆盖不可靠；
- 构建后出现缺字或错误字重；
- 需要突破必要字重才能维持页面。

回退时：

1. 移除自托管字体文件和引用；
2. 启用 `frontend/DESIGN.md` 指定的系统字体栈；
3. 重跑两档桌面截图和文字溢出检查；
4. 在交付报告中说明触发条件和结果；
5. 不以此为由暂停其他已可继续的视觉工作。

## 10. 完成定义

阶段 3B 只有同时满足以下条件才完成：

- 三张门槛页先获得用户明确确认；
- 所有目标页面符合 `frontend/DESIGN.md`；
- 三世界场景和 Xiaotuo 核心姿态达到接近最终品质；
- 两档桌面逐屏截图齐全；
- 字体实际发布压缩合计严格小于 10 MB，或已完整回退系统字体栈；
- 类型检查、测试和生产构建通过；
- 功能、接口、路由、评分语义和后端推导无回归；
- 禁止机制没有重新出现；
- git diff 仅包含获授权的阶段 3B 范围；
- 已形成主控要求的独立 Git 检查点；
- 已主动向主控回传完整结果；
- 已停止，没有启动阶段 4。

## 11. 停止条件

出现以下任一情况，立即停止扩展并向主控报告：

- 用户尚未确认三张视觉门槛页；
- 需要修改后端、接口契约、评分语义或数据模型；
- 发现功能基线失败且无法证明由环境造成；
- 工作树存在与本任务重叠且归属不明的修改；
- 字体授权、体积或字符覆盖无法可靠验证；
- 接近最终品质的插画无法在既定边界内交付；
- 需要引入本 brief 明确禁止的机制才能继续；
- 用户要求改变固定产品结构；
- 阶段 3B 已完成但尚未收到阶段 4 的独立授权。

停止不等于自行扩大范围。施工 session 只报告证据、影响和所需决策，等待主控与用户确认。
