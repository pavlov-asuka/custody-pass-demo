# 学员可见文字去 AI 味施工计划

## 1. 目标与范围

本阶段只治理学员可见文字，不调整多邻国式视觉、小托资产、三世界、长地图、色彩、庆祝反馈、页面布局或交互机制。

正式范围：

- 前端页面、按钮、状态、气泡、空状态、错误和确认文案；
- 后端返回的练习反馈、评分证据、补学标题与原因；
- `ACCOUNTING_2026.08.10` 的 48 条正式路线中学员可见文字；
- 内部字段、活动类型和状态在显示层的人类可读映射；
- 与上述文案直接相关的测试、现役文档和校验脚本。

冻结不动：

- 48 条路线、39 条 REQUIRED、地图拓扑、路线 ID 和发布边界；
- 四环节、异步四维评分、75 分通过线、硬性必达、定向补学、综合实务重做和历史记录；
- 数字、公式、答案、Rubric、资料关系、状态机、接口和数据模型；
- `frontend/DESIGN.md` 的视觉基线。

## 2. 需要移除的四类语言

### 2.1 泛化陪练腔

例如“再想一步”“一步一步来”“更容易进步”“及时看见成长”。友好可以保留，但必须落到当前业务对象、证据或下一动作。

### 2.2 作者旁白腔

减少“本案例、本路线、题面、请用一句可追溯的正常业务结论”等课程自指。上下文已明确时直接写资料、动作和结果。

### 2.3 评测器腔

不使用“能力尚未充分体现”“结构化作答未满足”等抽象评价作为唯一反馈。公开证据必须指出具体字段、来源、金额、状态、公式、勾稽关系或缺失结论。

### 2.4 接口/规格说明腔

内部 `fieldId`、`optionId`、`FIELD_MAP`、`CALCULATION`、`RECONCILIATION`、`SHORT_TEXT` 和非业务型状态码不得直接作为用户解释。内部值保持不变，只增加显示层中文。

## 3. 写作规则

1. 系统文案采用“状态 + 用户能做什么”。
2. 教学文案采用“具体对象 + 具体动作 + 可核对结果”。
3. 错误反馈采用“证据差异 + 需要重查的位置”，不评价人格和抽象能力。
4. 小托每次只说当前场景的一句具体话，不承担常驻励志教练职责。
5. 结果页先给结论，再给证据，最后给下一动作。
6. 用“读取、计算、登记、结转、冲销、核对、结平、归档”替代无信息量的“完成、形成、闭环、链条”。
7. 风险边界只在必要位置说明一次，不在材料、工作项和提交说明中重复免责声明。
8. 专业术语、合法业务状态和必要精度不得为了口语化而删改。

## 4. 反同义词门禁

每项改动必须至少满足一项：

- 增加具体业务对象；
- 指明资料或字段；
- 指明金额、状态或计算关系；
- 明确用户下一动作；
- 删除重复的课程自指或免责声明；
- 将内部工程标签映射为业务中文。

只替换形容词、同义词、标点或句尾语气的修改退回。

## 5. 施工批次

1. 前端静态文案与内部标签显示映射；
2. 后端练习反馈、评分证据和补学公开文字；
3. 五条样板路线：`ACC-LIFE-DAILY-003`、`ACC-STOCK-TRADE-001`、`ACC-CBF-BOUNDARY-001`、`ACC-MF-EIR-002`、`ACC-ED-QUARTERLY-004`；
4. 样板盲审通过后，按模块迁移其余 43 条路线；
5. 重复短语扫描、全量测试、浏览器试学和现役文档收口。

各模块分配给路径互不重叠的 `gpt-5.6-luna`、`max` 子代理；主控统一检查差异、处理跨层显示映射并运行最终验证。
